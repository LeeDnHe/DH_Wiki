# Claude Code를 활용한 개발 워크플로우

> 게임 개발자로서 Unity 기반 VR/WebGL 프로젝트와 TypeScript 기반 1인 개발 프로젝트에서 공통으로 운용 중인 AI 증강 개발 구조.

## 3-Agent 파이프라인

- **Planner** — 요구사항을 받고 작업을 분해. 어떤 파일을 어떻게 고칠지 먼저 설명하고 승인받기 전까지 코드 작성 금지.
- **Generator** — Planner의 계획에 따라 코드 생성.
- **Evaluator** — Generator의 결과를 점검. 빌드·타입·런타임 오류, 컨벤션 준수, 핵심 로직 일관성 관점에서 피드백.

각 역할은 `.claude/agents/`에 프롬프트로 분리되어 있고, 슬래시 커맨드로 특정 에이전트만 호출 가능. 파일 변경이 5개 이상 얽히는 작업에서 전체 파이프라인을 기동.

### 검증 범위의 명확한 분리
Evaluator는 직접 플레이 테스트하지 않음. 빌드 오류와 스크립트 오류(타입/런타임)까지만 검증하고, 실제 감각 확인은 사람이 담당. "AI에 위임 가능한 검증"과 "사람이 봐야 하는 검증"의 경계를 미리 정해두면 속도와 품질을 함께 잡기 쉬움.

## CLAUDE.md 계층

- **Register (최상위 규칙)** — 프로젝트 비전과 절대 규칙. 5~6줄 이내로 유지.
- **Cache (라우팅 테이블)** — "이 작업을 할 때는 저 문서를 보라" 식의 매핑표. 매 세션 시작 시 참조.
- **RAM (상세 스펙)** — 아키텍처, 컨벤션, 서비스 목록, 스테이지 스펙. 필요할 때만 로드.
- **Disk (전체 코드베이스)** — 직접 탐색. 전체를 컨텍스트에 넣지 않음.

라우팅 테이블로 필요한 문서만 골라 참조해야 토큰이 덜 낭비됨. 모든 지식을 루트 CLAUDE.md에 몰아넣으면 계층이 무너지고 실제로 읽히는 정보가 오히려 줄어듦.

## 프로젝트별 적용 방식

- **XREAL Two of Us (Unity 6, 소규모 팀)** — Planner가 비대칭 협동 시점별 게임플레이 상태 설계까지 포함해 작업을 분해. Evaluator는 Unity/C# 컨벤션과 Quest 성능 관점을 추가로 검사.
- **PBV 스마트 설계 시스템 (Unity WebGL + 아키모스 웹 연동, 소규모 팀)** — `dynamic_properties.json` 같은 데이터 스키마가 차량/부품 동작을 정의하므로, Planner가 스키마 변경의 파급 범위를 먼저 분해. Evaluator는 JS↔Unity 콜백 계약과 커맨드 패턴 Undo/Redo 일관성을 추가로 검사.
- **FolderEscape (TypeScript + Vite + Tauri, 1인 개발)** — 파일탐색기 UI 통일성과 "플랜 → 승인 → 코딩" 절차를 Register에 명시. 공용 로직은 서비스 레이어(`src/services/`)로 강제 흡수해 핸들러는 고유 로직만 담당.

## 하지 말 것

- 매 세션마다 전체 코드베이스를 컨텍스트에 넣기 → 토큰 낭비.
- 모든 지식을 루트 CLAUDE.md에 몰아넣기 → 계층 붕괴.
- Evaluator 없는 생성 → 실수 누적.
- AI에게 플레이테스트 요구 → 빌드/타입 검증까지가 AI의 경계.
