# PBV 설계 툴을 만들면서 내가 짠 구조

> Unity 클라이언트 개발자로 PBV 스마트 설계 시스템을 구현하면서 실제로 만든 부분 위주로 정리. 일반론 대신 프로젝트에서 있었던 일을 적어두려고 한다.

## 이 프로젝트에서 내가 맡은 부분

- 아키모스(OnMakers) 플랫폼과의 **JSON 양방향 통신**
- `dynamic_properties.json` **스키마 설계**
- UI Toolkit 기반 **런타임 계층구조(Hierarchy) 뷰**
- UI Toolkit 기반 **커스텀 속성창(Inspector)**
- **커스텀 uGUI 드롭다운** (UI Toolkit 밖)
- **URP DecalProjector** 기반 곡면 데칼 UX
- 대규모 부품 카탈로그의 **Addressable 로드**
- 배치·편집 행동의 **Command 기반 Undo/Redo**

## JS ↔ Unity 양방향 통신

브라우저 안에 올라간 Unity WebGL 빌드가 아키모스 플랫폼과 데이터를 주고받는다.

- **웹 → Unity**: `unityInstance.SendMessage`로 명령 전달.
- **Unity → 웹**: jslib 콜백으로 상태 변화 송출.
- 실제로 많이 부딪혔던 건 JS 이벤트 루프와 Unity 프레임 루프 사이의 타이밍 차. 입력·응답 경계에서 타임아웃·중복 호출·대기 상태를 케이스별로 처리했다.

## `dynamic_properties.json` 스키마

차량 5종 × 부품 40+종의 동작을 C# 코드에 하드코딩하지 않고 데이터로 서술했다. 한 부품 엔트리에 다음을 넣는다.

- **물리 속성** — 질량·마찰 등 런타임이 바로 쓰는 값.
- **배치 제약** — Dot/Line/Plane 중 어떤 기하에 붙는지.
- **스폰 후 자동 동작** — 카메라 이동, 자식 오브젝트 숨김, 도어 개방 등 "스폰 직후 무조건 일어나야 하는" 행동.

스키마가 바뀌면 런타임 동작이 조용히 변할 수 있어서, 엔트리 로더 쪽에서 누락·타입 불일치를 명시적으로 잡아내도록 해뒀다.

## 런타임 계층구조(Hierarchy) 뷰 — UI Toolkit

유니티 에디터의 Hierarchy 창과 비슷한 "런타임용" 계층구조 뷰를 UI Toolkit으로 만들었다.

- 현재 씬에 배치된 차체·부품을 트리로 표시하고, 선택/포커스/폴드 상태를 공유.
- 트리 노드 클릭 → 씬 선택, 씬 선택 → 트리 포커스가 양방향으로 동기화.
- 자주 쓰는 동작(숨김/잠금/삭제)은 노드 우측 인라인 버튼으로.

## 커스텀 속성창(Inspector) — UI Toolkit

선택된 오브젝트의 속성을 편집하는 인스펙터를 UI Toolkit으로 따로 구현했다.

- 속성 정의는 `dynamic_properties.json` 쪽 스키마를 따라가므로, 인스펙터 필드 구성이 데이터에서 결정된다.
- 숫자·토글·슬라이더·드롭다운 등 필드 타입별 위젯을 조합해 한 오브젝트 = 하나의 인스펙터 패널로 조립.
- 값 변경은 즉시 씬에 반영하되, 실제 커밋은 Command로 감싸 Undo/Redo 큐에 올린다.

## 커스텀 uGUI 드롭다운

UI Toolkit만으로 해결 안 된 케이스가 있어서 uGUI 쪽 드롭다운을 따로 만들었다.

- 애니메이션: DOTween.
- 반응형: 9-Slice 스프라이트.
- 브라우저 포커스 전환 시 입력이 유실되는 문제가 있어서, focus/blur 경계에서 상태를 복구하는 로직을 넣었다.

## URP DecalProjector로 곡면 데칼

차체 곡면 위에 스티커·로고를 붙이는 UX. 직접 UV로 계산하면 곡면이 심한 위치에서 왜곡이 커져서 DecalProjector로 통일했다. 배치 UX 관점에선 "투영 방향"과 "프리뷰"가 매칭돼야 해서, 드래그 중인 데칼의 프리뷰 프로젝터와 확정 후 프로젝터가 같은 공간에서 동작하도록 맞췄다.

## Addressable로 카탈로그 로드

- 차량 5종 × 부품 40+종을 전부 씬에 올려두면 메모리와 로딩 시간이 모두 문제.
- 카탈로그 진입 시 해당 그룹만 로드, 선택 해제 시 Release. `AsyncOperationHandle`을 보관해서 누락 없이 해제.
- 자주 전환되는 뷰에선 LRU 크기를 작게 두고, 전환이 드문 뷰에서는 미리 로드.

## Undo/Redo

배치·속성 변경·삭제를 전부 Command 객체로 감싸서 스택으로 관리. 웹(아키모스) 쪽에서 트리거된 변경도 동일 큐에 실어서, Undo/Redo가 입력 출처에 상관없이 일관되게 동작하도록.
