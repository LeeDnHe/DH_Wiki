# FolderEscape를 혼자 만들면서 정리해둔 규칙

> FolderEscape(TypeScript + Vite + Tauri, OS 해킹 퍼즐 게임)를 혼자 만들면서 `CLAUDE.md`에 정리해둔 규칙들. 지키려고 노력하는 것들을 적어둔 정도.

## 핵심 규칙

- **파일탐색기 UI 통일성** — 거의 모든 스테이지가 파일탐색기 안에서 벌어져서, 기존 탐색기 UI 패턴을 재사용하는 걸 기본으로 삼는다. 새 UI가 필요하면 먼저 상의.
- **플랜 → 승인 → 코딩** — 뭘 만들지, 어떤 파일을 건드릴지 먼저 얘기하고 승인받은 뒤에 코드를 쓰려고 한다. Claude Code와 함께 일할 때도 같은 순서로.
- **서비스 레이어** — 공용 기능은 `src/services/`에 두는 편이다. 스테이지 핸들러에는 그 스테이지 고유 로직만 두려고 한다.
- **사운드** — 효과·연출·액션에는 가능한 한 사운드를 붙여두려고 한다.
- **토큰 절약** — 라우팅 테이블로 필요한 문서만 참조하고, `Explorer.ts` 같이 큰 파일을 통째로 읽지 않으려고 한다.
- **검증 범위** — 플레이 테스트는 직접 한다. 에이전트는 빌드와 스크립트 오류(타입/런타임) 쪽 확인까지만 맡긴다.

## 왜 이렇게 나눴나

거의 모든 스테이지가 "파일탐색기 UI 안에서 뭔가를 한다"는 구조라, 스테이지별로 UI를 각자 만들면 통일성이 흐트러지기 쉽다. 반대로 한 곳에 전부 몰면 핸들러가 금방 커진다. 그래서 공용 기능은 서비스 쪽에 두고 스테이지는 자기 로직만 담당하도록 나눠봤다.

## 라우팅 테이블

`CLAUDE.md`에 작업 종류별로 볼 문서를 매핑해뒀다.

- 아키텍처 / 핵심 구조 → `.claude/index/architecture.md`
- UI 규칙 / 코딩 컨벤션 → `.claude/index/conventions.md`
- 스테이지 목록 / 개별 스테이지 → `.claude/index/stages-overview.md`
- 스테이지 기본 구성 템플릿 → `.claude/specs/stage-template.md`
- 서비스 레이어 상세 → `.claude/index/services.md`
- 3-Agent 파이프라인 → `.claude/agents/`

세션마다 필요한 문서만 참조하려는 목적. 루트 `CLAUDE.md`가 너무 커지지 않았으면 해서.

## Claude Code와 일하는 흐름

- **새 스테이지 추가** — Planner가 라우팅 테이블을 먼저 보고, stages-overview와 stage-template만 로드하는 식.
- **UI 손볼 때** — conventions 문서를 추가로 참조. 통일성 쪽 규칙을 놓치면 Evaluator 단계에서 한 번 더 확인.
- **공용 연출 추가** — services 문서를 먼저 보고, 없으면 서비스로 만들지 의논. 핸들러 안에 직접 넣지 않는 쪽으로.

## 문서화를 해두는 이유

혼자 작업하다 보니 결정 사항을 문서로 남겨두지 않으면 시간이 지나서 구조가 흐트러지기 쉬워서, 간단하게라도 적어두려고 한다.
